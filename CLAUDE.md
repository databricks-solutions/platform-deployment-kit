# One-Click Databricks Deployer

Browser-only static app that generates deployable Databricks Terraform projects for AWS,
Azure, and GCP from a form. There is no backend: the app source in `deploy/` is built into
`dist/` and served as static files. ZIP generation runs entirely in the browser.

## Build

- `npm run build` runs `scripts/build.js`: copies `deploy/` to `dist/`, vendors the upstream
  Terraform sources with SHA-256 hashes (`scripts/vendor-terraform.js`, config in
  `config/upstreams.json`), and writes `dist/version.json`.
- `npm run build:libs` (`scripts/copy-libs.js`) copies vendored libraries (Bootstrap, JSZip,
  Handlebars, Choices.js, fonts) into `deploy/libs` and `deploy/fonts`. Runs on `postinstall`.

## Testing

There is ONE entry point for the whole test and quality pipeline, and it runs locally
without GitHub Actions:

```bash
./scripts/test-all.sh
```

Stages, in order, fail-fast: `build` -> `deps` (npm audit) -> `unit` (Vitest + coverage) ->
`e2e` (Playwright + optional coverage). Flags:

| Flag | Effect |
|------|--------|
| `--only <stage>` | Run one stage: `build`, `deps`, `unit`, or `e2e`. |
| `--skip <stage>` | Skip a stage (repeatable). |
| `--e2e-coverage` | Run e2e under `playwright.coverage.config.js` (produces the app.js report). |
| `--strict-audit` | Make a production dependency vulnerability fail the run (default: warn only). |
| `--audit-level=<lvl>` | Audit gate severity for production deps (default `high`). |
| `--ci` | CI mode: sets `CI=1` (Playwright retries, 1 worker, html report). |

Interactive and single-spec runs use the npm scripts, not a separate script:

```bash
npm run test:unit                         # Vitest unit tests
npm test                                  # all Playwright e2e tests
npm test -- tests/e2e/aws-smoke.spec.js   # a single e2e spec
npm run test:headed                       # e2e with a visible browser (also test:ui, test:debug)
npm run test:coverage                     # e2e with the app.js coverage report
```

### Coverage model

Two layers, by design:

- Unit (Vitest, V8) covers the pure logic modules in `deploy/js`. Per-file thresholds are
  enforced in `vitest.config.js` and fail the run on regression. `app.js` and
  `help-content.js` are excluded here (app.js is an e2e responsibility; help-content.js is
  static copy). Report in `coverage/unit/`.
- End-to-end (Playwright, V8 in the browser) covers `app.js`, the DOM/SPA controller, via
  `--e2e-coverage`. Reporting is generated by `scripts/collect-coverage.js` (its
  `SOURCE_FILES` list must stay in sync with `deploy/js`). Report in `coverage/playwright/`.

`scripts/generate-coverage-report.js` is unused (no references); do not wire new work to it.

### Console errors are a test failure

Every e2e test runs through the fixture in `tests/helpers/coverage-fixture.js`, which fails
the test on any `console.error` or uncaught `pageerror`. Add known-benign messages to the
documented allowlist in that file rather than silencing the check.

### Node version

`.nvmrc` pins Node 20. Unit tests run on Node 18+. The Playwright browser install needs
Playwright >= 1.63 on Node 22+ (this project uses 1.63), because older Playwright calls a
`fs.rmdir` API removed in Node 22.

## Deployment

`scripts/deploy.sh` is the SINGLE source of deploy logic, used identically by local
(`npm run deploy`) and by CI (the workflow's `deploy` job calls the same script). It:

1. Runs `./scripts/test-all.sh --ci --strict-audit`. If any stage fails (including a
   production dependency vulnerability), the deploy aborts. This also builds `dist/`.
2. Copies `dist/` into a temporary repo and force-pushes it to `gh-pages`.

Auth is the only environment difference, handled inside the script: in CI it pushes with
`GITHUB_TOKEN` (`x-access-token` URL from `GITHUB_REPOSITORY`); locally it uses the `origin`
remote and the developer's credentials. Never bypass the gate. Do not add a separate
`npm run build` in `deploy.sh` or in the workflow; the pipeline already builds `dist/`.

### gh-pages is the user-facing branch — protect it

`gh-pages` is what serves end users, so nothing un-gated must reach it. The code already
guarantees this: every write to `gh-pages` goes through `deploy.sh`, which runs the full
gated pipeline first, in both local and CI.

When GitHub Actions is enabled, ALSO add GitHub branch protection so humans cannot push
around the pipeline. Apply this together with enabling Actions (applying it earlier would
block the current local `npm run deploy`). Representative command (replace `OWNER/REPO`, and
adjust the actor allowed to push once the deploy runs in CI):

```bash
gh api -X PUT repos/OWNER/REPO/branches/gh-pages/protection \
  -H "Accept: application/vnd.github+json" \
  -F enforce_admins=true \
  -F required_status_checks=null \
  -F required_pull_request_reviews=null \
  -F 'restrictions[users][]=' -F 'restrictions[teams][]=' -F 'restrictions[apps][]=github-actions' \
  -F allow_force_pushes=true -F allow_deletions=false
```

This restricts pushes to the GitHub Actions app (so only the gated deploy job can publish),
keeps force-push enabled for that generated branch, and blocks branch deletion.

## CI portability

`.github/workflows/ci.yml` is a THIN wrapper. It only provisions the environment (checkout,
Node from `.nvmrc`, `npm ci`) and then calls the scripts:

- `test` job (non-tag pushes): `./scripts/test-all.sh --ci --e2e-coverage` (the script
  installs the Playwright browser itself, with `--with-deps` under CI).
- `deploy` job (tags): `./scripts/deploy.sh`.

Keep ALL test/build/deploy logic in the scripts, never in the workflow, so local and CI stay
identical and re-enabling Actions needs no code change.

## Dependency security

`npm audit` is part of the pipeline. Keep production dependencies clean (`npm audit fix`);
`--strict-audit` (used by the deploy gate) fails on any production vulnerability at or above
the audit level.

## Scripts reference

| Script | Purpose |
|--------|---------|
| `scripts/build.js` | Build `dist/`, vendor upstream Terraform, write `version.json`. |
| `scripts/copy-libs.js` | Copy vendored libraries and fonts into `deploy/`. |
| `scripts/vendor-terraform.js` | Fetch upstream Terraform, generate the hashed manifest. |
| `scripts/dev.js` | Local dev server with live reload (`npm run dev`). |
| `scripts/run.sh` | Build and serve `dist/` statically (`npm start`). |
| `scripts/test-all.sh` | Single test/quality pipeline entry point (see Testing). |
| `scripts/collect-coverage.js` | Convert Playwright V8 coverage to the e2e report. |
| `scripts/deploy.sh` | Gated publish of `dist/` to `gh-pages` (`npm run deploy`). |
